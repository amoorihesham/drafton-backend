## Project Overview

DraftOn is a SaaS platform for managing and automating the creation of PRD's and Proposal documents. It serves as a bridge between freelancers (providers) and their clients, streamlining the entire document lifecycle from creation to delivery.

**Tech-Stack**:

-Fastify 5.8.4
-TypeScript 6.0.2
-Drizzle ORM 0.45.1
-PostgreSQL hosted on NEON
-Redis hosted on UPSTASH
-Vitest 4.1.2

## Commands

```bash
pnpm dev              # Development with watch mode
pnpm build            # Production build (tsup → ESM)
pnpm start            # Run built app

pnpm test             # Run all tests once
pnpm test:watch       # Watch mode
pnpm test:coverage    # With v8 coverage report
npx vitest run <path> # Run a single test file
npx vitest run --grep "<test name>"  # Run tests matching a pattern

pnpm typecheck        # Type-check without emitting

pnpm db:generate      # Generate Drizzle migration files from schema changes
pnpm db:migrate       # Apply pending migrations
pnpm db:push          # Sync schema directly (skips migration files)
pnpm db:studio        # Open Drizzle Studio visual DB manager
```

## Architecture

we follow a module-based architecture where each domain feature lives in `src/modules/<name>/` with this layout as example:

```
auth/
├── auth.module.ts      # DI wiring — builds and returns {controller, routes}
├── auth.controller.ts  # HTTP request handlers
├── auth.service.ts     # Business logic
├── auth.routes.ts      # Fastify route registration
├── types/              # TypeScript types & DTOs
├── schemas/            # @sinclair/typebox request/response schemas
├── utils/              # JWT, OTP, bcrypt helpers
├── constants/          # Error codes & user-facing messages
├── interfaces/         # IRepository, ITokenStore contracts
└── services/           # Sub-services (e.g. mail dispatching)
```

**Shared infrastructure** (`src/shared/`):

- `errors/` — `AppError` base + typed subclasses (`AuthError`, `NotFoundException`, …)
- `http/` — response helpers and HTTP constants
- `services/mail/` — nodemailer wrapper with Brevo SMTP

**Database** (`src/db/`):

- Schema definitions in `src/db/schema/` (Drizzle table objects)
- Repositories in `src/db/repositories/` implement interfaces from the module
- Migrations auto-generated by Drizzle Kit into `src/db/migrations/`
- Connection via `pg` pool, configured by `DATABASE_URL` + `DB_POOL_SIZE`

**Session / token model**:

- Access token: short-lived JWT (default 15 min), returned in `HttpOnly` cookie
- Refresh token: long-lived JWT (default 7 days), stored in Redis at key `session:{userId}:{deviceId}`
- Multi-device support — each device has its own refresh token slot

**Path alias**: `@/*` maps to `./src/*` (configured in `tsconfig.json` and respected by `tsup`).

## Testing

Tests live in `src/tests/` with `unit/` and `integration/` subdirectories.

Vitest runs with `pool: "forks"` and `poolOptions.forks.singleFork: true` so tests are sequential — this avoids port collisions when spinning up the Fastify server in integration tests.

Integration tests boot a full Fastify instance against a real test database (`.env.test`). Unit tests mock the repository and token-store interfaces.

## Environment Variables

Copy `.env.example` to `.env`. Required variables:

| Variable                                              | Notes                             |
| ----------------------------------------------------- | --------------------------------- |
| `DATABASE_URL`                                        | Postgres connection string (Neon) |
| `DB_POOL_SIZE`                                        | Default 10                        |
| `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET`            | Hex strings                       |
| `JWT_ACCESS_TOKEN_EXPIRY`                             | Milliseconds, default 900000      |
| `JWT_REFRESH_TOKEN_EXPIRY`                            | Milliseconds, default 604800000   |
| `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` | Upstash serverless Redis          |
| `SMTP_HOST/PORT/USER/PASS/FROM`                       | Brevo SMTP relay                  |
| `FRONTEND_URL`                                        | Used for CORS and email links     |
| `SALT_ROUNDS`                                         | bcrypt rounds, default 12         |
| `OTP_EXPIRY_MINUTES` / `RESET_OTP_EXPIRY_MINUTES`     | Default 15 / 30                   |

Config is validated at startup via `@fastify/env` + `@sinclair/typebox` schema in `src/config/index.ts` — the app will not start if required variables are missing.
